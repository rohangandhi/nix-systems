# nix-systems
NixOS flake for host machines and host-provided VM launchers.

## Systems in this flake
- `.#nixosConfigurations.zion-alpha`: primary host configuration.

## Prerequisites
- Run commands from this directory: `/home/ephemeral/n-data/nix/systems`.
- Use a NixOS host with flakes enabled, or prefix commands with:
  `NIX_CONFIG="experimental-features = nix-command flakes"`.

## Quick inspection
- Show available outputs:
  ```bash
  nix flake show .
  ```
- Build host closure without switching:
  ```bash
  nix build .#nixosConfigurations.zion-alpha.config.system.build.toplevel
  ```

## Using `zion-alpha` (host)
- Apply configuration to the running machine:
  ```bash
  sudo nixos-rebuild switch --flake .#zion-alpha
  ```
- Build and test without making it the boot default:
  ```bash
  sudo nixos-rebuild test --flake .#zion-alpha
  ```

## Installing `zion-alpha` from a live installer
`install.sh` contains the current install flow (disk unlock/format/mount + `nixos-install`).

Run from a NixOS live environment after cloning this repo:
```bash
cd /path/to/repo/systems
sudo bash ./install.sh
```

## Using `matrix-one` (VM for isolated loops)
Global host command (available after `nixos-rebuild` on `zion-alpha`):
```bash
matrix-one-vm
```

This command is generated by the host configuration and executes the VM runner
directly from the Nix store (no hardcoded workspace path lookup at runtime).
Matrix VM definitions and launcher command generation are both declared in
`./matrix/systems.nix`.

Ephemeral disk per launch:
```bash
NIX_DISK_IMAGE=/tmp/matrix-one-$(date +%s).qcow2 matrix-one-vm
```

Serial console mode:
```bash
NIX_DISK_IMAGE=/tmp/matrix-one-$(date +%s).qcow2 matrix-one-vm -nographic
```

Reuse a persistent disk between runs:
```bash
NIX_DISK_IMAGE=/tmp/matrix-one-persistent.qcow2 matrix-one-vm
```

Install Node/Bun CLI packages globally inside the VM:
```bash
npm install -g <package>
bun install -g <package>
```

`matrix-one` configures npm globals under `~/.npm` and adds `~/.npm/bin` plus
`~/.bun/bin` to `PATH` on login. Those installs persist when you reuse the
same `NIX_DISK_IMAGE`.

## `matrix-one` isolation and dependency behavior
- Host `/nix/store` is mounted read-only into the guest as `/nix/.ro-store`.
- Guest `/nix/store` is an overlay:
  lower layer = host read-only store, upper layer = guest writable tmpfs.
- Result: the VM reuses host Nix dependencies and can also install missing Nix deps.
- Guest writes do not modify host `/nix/store`.
- Guest-added Nix store paths are ephemeral by default (cleared when VM stops).
- Default temporary host exchange mounts (`/tmp/shared`, `/tmp/xchg`) are disabled.

## `matrix-one` network model
- Guest direct access to the host and LAN is blocked with `virtualisation.restrictNetwork = true`.
- HTTP/HTTPS client traffic is expected to use the forwarded host Squid proxy at `http://10.0.2.10:3128`.
- The guest sets `networking.proxy.default = "http://10.0.2.10:3128"` so proxy-aware tools inherit that endpoint automatically.
- Additional host services must be exposed explicitly with extra `virtualisation.forwardPorts` entries.
